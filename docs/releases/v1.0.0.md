# RMMWay v1.0.0 Release Notes

**Release date:** 2026-09-10

Version 1.0.0 marks the first stable release of RMMWay, a self-hosted
remote monitoring and management platform. This release includes the
complete Wave 0 through Wave 4 feature set across all three lanes.

## Major Features

### Fleet Monitoring

- Live device list with online/offline status
- Continuous metrics collection (CPU, memory, disk, network, uptime)
- Dynamic baselining with no-threshold anomaly detection
- Deduped alert inbox with auto-resolution
- Agent log collection and browsing

### Remote Management

- One-click device enrollment via one-time tokens
- Command dispatch (reboot, run script)
- File transfer (pull and push)
- Remote session viewing (phase 1, view-only)
- Live server-sent-events stream

### MSP / Multi-Tenant

- Client/tenant model with device assignment
- Per-client device list and alert scoping
- Multi-client dashboard with summary tiles

### Security

- Mutual TLS agent enrollment and communication
- JWT authentication with refresh
- Per-command capability tokens
- Signed agent binaries (minisign) and signed Docker images (cosign)
- Signed auto-updates with pinned release key

### Integrations

- Signed webhooks (HMAC-SHA256)
- SSE event stream with catch-up
- Per-client export (Parquet + JSON)
- Meilisearch device search with command palette

### Automation

- Event-driven flow automation (triggers → actions)
- Self-healing playbooks (restart service, etc.)
- Maintenance windows (per device/tag/client)
- Cron flow triggers

### Reporting & Compliance

- Scheduled and on-demand reports
- Fleet status, device, patch compliance, license compliance, uptime/SLA
- CSV and PDF output formats
- Report history and download

### Patch Management

- Windows Update query/approve/apply
- Third-party software (MSI/APKB) installation
- Patch policy configuration

## Breaking Changes

None — this is the first stable release.

## Upgrading from Pre-Release Builds

If you're running a pre-release build, follow the upgrade notes in the
CHANGELOG. Key database migrations (0001–0016) will be applied
automatically on server startup.

## Known Issues

- Remote session frame capture may be slow on high-CPU-load devices
- macOS agent requires manual Screen Recording permission grant
- Headless Linux devices require a local VNC session for screen capture
- Initial baselining may take up to 45 days for seasonal patterns

```
ghcr.io/welcometotheweb/rmmway:1.0.0

```

### Verification

Agent binaries are signed with minisign. Verify with:

```sh
minisign -Vm rmmway-agent-linux-amd64 -P '<minisign public key>'
```

The public key is at `keys/minisign.pub` in the release tarball.

Docker images are signed with cosign. Verify with:

```sh
cosign verify ghcr.io/welcometotheweb/rmmway:1.0.0
```
